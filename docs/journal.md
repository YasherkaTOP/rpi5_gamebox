**Отклонения от плана и спецификации.**

1. Носитель — microSD, а не USB SSD (§3.1, §3.6). SSD вышел из строя; владелец поставит USB SSD сам, без повторных замеров.
2. Образ — с рабочим столом (`stage4`, `lightdm`, `graphical.target`), а §4 требует «без рабочего стола». Не исправлено.
3. SSH с паролем вместо входа только по ключу — решение владельца.
4. Речь с 0,5 м на 1,5 дБ выше шума — критерий §3.6 не выполнен; владелец принял до калибровки.
5. Стресс 15 мин вместо часа, и без нагрузки на Hailo (ошибка имени модели в скрипте, см. ниже). Час нагрузки по плану закрывается в блоках 7 и 21.
6. RTC в отчёте не держал время (после отключения питания — 1970-01-01, `battery_voltage=0`). 23.11.2026 владелец исправил батарейку и проверил вручную; данными отчёта ещё не подтверждено. `hwclock` в образе нет (`util-linux-extra`).
7. Абсолютная задержка HDMI не измерена (§3.6) — переносится в блок 5.

**Исправлено в скриптах по ходу блока.**

- `50_stress.sh`: модель по умолчанию `qwen2-instruct:1.5b`; проверка модели до старта; ответы `hailo-ollama` с `"error"` при HTTP 200 считаются неудачными.

**Расхождение с реальностью: релиз активирован, но не запускается.** После активации команда `sudo -u gamebox /opt/gamebox/current/.venv/bin/gamebox smoke` отвечала `sudo: unable to execute ...: No such file or directory`, хотя файл существовал и права были верные. Причина — ошибка установщика, а не устройства: venv создавался внутри `.pending-<id>-XXXX`, console-script `gamebox` получал абсолютный shebang на этот временный путь, после `pending.rename(target)` путь переставал существовать. Ядро не находит интерпретатор и возвращает ENOENT на сам скрипт. Smoke при установке проходил, потому что запускался **до** переименования — то есть проверка не покрывала финальное состояние.

**Исправление в `deploy/install_release.py`.** Порядок изменён на «перенос → починка shebang → smoke из финального пути»:
- `rewrite_shebangs(venv: Path, old_root: Path, new_root: Path) -> int` — переписывает префикс `old_root` на `new_root` в первой строке текстовых файлов `.venv/bin`, пропуская симлинки и бинарники; пути приводятся к абсолютным, операция идемпотентна;
- `resolve_user(name: str) -> tuple[int, int]` — `pwd` импортируется внутри функции, поэтому модуль импортируется и на Windows;
- `ensure_service_dirs(root, runtime, uid: int, gid: int)` — сигнатура изменена с `entry: pwd.struct_passwd` на пару `uid/gid` (следствие предыдущего пункта);
- smoke запускается из `target/.venv/bin/gamebox`, а не из `pending`;
- в `except` удаляется актуальный каталог (`installed`), а не только `pending`, иначе повторный деплой упирался бы в «Релиз уже существует»;
- установщик печатает промежуточную строку `{"relocated": ..., "shebangs_fixed": N}`.
